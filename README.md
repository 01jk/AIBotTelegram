# Telegram AI-компаньон

## Запуск одной командой

На сервере с Docker и Compose 2.24+ выполните из корня проекта.

```sh
docker compose up --build
```

Compose соберёт образ, запустит приложение и создаст том для SQLite и
Telegram-сессии. В контейнере они хранятся в `/app/data`. Образ использует шаблоны модели и персоны. Для собственных настроек укажите пути MODELS_PATH и PERSONA_PATH к файлам в подключённом томе. Команда работает без `.env`
и запускает локальное хранилище в `OBSERVE` с `DRY_RUN=true` на новой базе.

На Windows с Python 3.11+ выполните в PowerShell из корня проекта. При первом запуске создайте локальные настройки из шаблонов.

```powershell
if (!(Test-Path models.yaml)) { Copy-Item models.example.yaml models.yaml }
if (!(Test-Path prompts/persona.yaml)) { Copy-Item prompts/persona.example.yaml prompts/persona.yaml }
.\start.ps1
```

Скрипт создаёт `.venv`, при необходимости устанавливает зависимости
и запускает приложение. SQLite должна поддерживать FTS5. Остановить
процесс в терминале можно через Ctrl+C.

Для локальных проверок в другом терминале из корня проекта.

```powershell
.\.venv\Scripts\python.exe -m aibottelegram healthcheck
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest -q
```

`init` применяет миграции и проверяет FTS5. `run` также делает это при старте
и обновляет локальную отметку времени каждые 5 секунд. `healthcheck` открывает
БД для чтения и возвращает код 0 при отметке возрастом до 20 секунд. После
штатной остановки отметка очищается, после аварийной она истекает.

## Вход в Telegram

Если управляющий бот отвечает, а личная сессия остановлена, отправьте
`/login` в личный чат управляющему боту. Откройте полученный QR на другом
экране. На телефоне откройте «Настройки → Устройства → Подключить
устройство» и отсканируйте QR. При истечении срока запросите новый через
`/login`. После проверки `EXPECTED_ACCOUNT_ID` сервер сохраняет сессию и
подключается снова. Проверить результат можно через `/status`.

Если Telegram требует пароль 2FA, завершите вход через интерактивный
терминал. При запуске на сервере и остановленной личной сессии выполните
из каталога проекта команды ниже. Терминал скрывает пароль при вводе.

```sh
docker compose exec companion python -m aibottelegram login --qr --replace
docker compose restart companion
```

1. Получите `API_ID` и `API_HASH` в [Telegram API Development Tools](https://my.telegram.org).
   Запишите их в локальный `.env`. В `EXPECTED_ACCOUNT_ID` укажите числовой
   ID своего аккаунта. В полном экспорте Telegram Desktop это поле
   `personal_information.user_id` в начале `dataSet/result.json`.
2. Оставьте `MODE=OBSERVE` и `DRY_RUN=true`. Выполните в обычном терминале
   команду `login`. Номер телефона виден при вводе. Терминал покажет способ
   доставки, выбранный Telegram. Код и пароль 2FA вводятся скрыто.
3. После сообщения `Telegram session verified.` выполните обычную команду
   запуска для своей среды.

В Docker используйте тот же том, что и фоновый процесс. Если сервис уже
запущен, сначала остановите его.

```sh
docker compose stop companion
docker compose run --rm --build companion login
docker compose up --build
```

Для локального входа на Windows используйте окружение, созданное
`start.ps1`. Перед входом остановите локальный фоновый процесс.

```powershell
.\.venv\Scripts\python.exe -m aibottelegram login
.\start.ps1
```

Если код не приходит, нажмите Enter на пустом поле кода, чтобы перейти
к QR. Для входа сразу через QR добавьте `--qr` после `login`. На телефоне
в Telegram откройте **Настройки → Устройства → Подключить устройство** и
отсканируйте QR с терминала, используя нужный аккаунт.

При совпадении ID в журнале появится `telegram_connected`. На этом этапе
воркер регистрирует в журнале метаданные новых входящих и исходящих сообщений
из чатов, разрешённых в SQLite. Telethon получает общий поток обновлений
аккаунта, приложение отфильтровывает его локально. Тексты сохраняются
в памяти только для разрешённых источников. У новой БД список разрешений пуст. Управляйте списком
командами отдельного Telegram-бота.

Фоновый процесс использует готовую сессию. Если файл отсутствует, аккаунт
не совпадает или сессия отозвана, воркер остановится и запишет причину
`telegram_worker_stopped`. Локальная проверка состояния продолжит работать.
При кратковременной потере связи воркер выполняет до четырёх повторов
с задержками 1, 2, 4 и 8 секунд. После минуты стабильной связи счётчик
сбоев сбрасывается.

Чтобы использовать существующий файл `.session`, сначала остановите
прежнюю автоматизацию и дождитесь закрытия её сессии. Поместите файл в
путь `TELEGRAM_SESSION_PATH` и выполните `login` для проверки ID.
По умолчанию используется `data/telegram.session`. На Linux установите
права `chmod 600` на импортированный файл. На Windows храните файл в каталоге,
доступном только вашей учётной записи. Блокировка действует для процессов
этого приложения в одном каталоге на одном хосте. При отзыве сессии
остановите воркер, уберите старый файл из настроенного пути и снова выполните
`login`.

## Управляющий бот

Создайте отдельного бота через `@BotFather` и сохраните его токен локально
в `CONTROL_BOT_TOKEN` в `.env`. В `OWNER_TELEGRAM_ID` можно указать ID
владельца. По умолчанию используется `EXPECTED_ACCOUNT_ID`. Доступ
ограничен этим ID и соответствующим приватным чатом. `ADMIN_IDS`
на этом этапе доступ не расширяет.

Перезапустите приложение, откройте личный чат с ботом и отправьте `/start`.
Меню можно снова открыть через `/menu`. В нём доступны режим, пауза,
черновики, разрешения чатов, модели и квоты. Для добавления чата или
сохранения своего варианта нажмите кнопку и ответьте на запрос бота.
Список черновиков можно листать. В настройках Reasoning можно включить
рассуждения DeepSeek для новых ответов.
Управляющий бот работает и в `DRY_RUN`, поскольку отвечает через отдельный
Bot API. Исходящие реплики личного аккаунта проходят через отдельный шлюз.

| Команда | Действие |
| --- | --- |
| `/status` | Показывает режим, сессию, активный разговор, очередь, расход бюджета и блокировку |
| `/stop`, `/pause`, `/resume` | Остановка отменяет ожидающие отправки и приостанавливает запросы к моделям и дайджест. `/resume` продолжает работу в выбранном режиме |
| `/mode [observe\|draft\|auto]` | Показывает текущий режим и описание или сохраняет выбранный режим |
| `/drafts [ID]` | Показывает последние черновики или полный текст черновика по номеру со ссылкой на исходное сообщение |
| `/approve ID`, `/reject ID` | Ставит актуальный черновик в очередь отправки или отклоняет его |
| `/prefer ID текст` | Сохраняет свою реплику до 120 символов как пример для будущих ответов в похожих ситуациях. Черновик остаётся как есть. Модель OpenRouter получает только сохранённый вариант из этой команды |
| `/chats [страница]` | Показывает разрешения по числовому ID чата |
| `/allow CHAT_ID [read_only\|draft_only\|auto_reply]` | Сохраняет разрешение. По умолчанию `read_only`. `/allow` без ID показывает описание прав |
| `/deny CHAT_ID` | Запрещает чтение новых событий и отключает внешнюю обработку |
| `/limits [chat CHAT_ID]` | Показывает глобальные или локальные лимиты |
| `/limits [chat CHAT_ID] ПАРАМЕТР ЗНАЧЕНИЕ` | Меняет лимит сразу и сохраняет расход |
| `/style` | Показывает состояние локального профиля стиля и число предпочтений |
| `/models`, `/providers` | Показывает маршруты и отдельный расход бесплатных и платных запросов |
| `/reasoning [on\|off]` | Показывает или меняет настройку рассуждений DeepSeek |
| `/reset_quota` | Начинает заново локальный подсчёт бесплатных запросов за минуту и день. Журнал сохраняется |
| `/openrouter_key` | Запрашивает новый ключ OpenRouter в личном чате владельца |
| `/external CHAT_ID on\|off` | Разрешает или отключает передачу отфильтрованных фрагментов группы в OpenRouter. Используйте отрицательный ID Telegram |
| `/forget CHAT_ID` | Удаляет локальные реплики, индекс, темы, сводки и источники этого чата |
| `/opportunities`, `/digest` | Показывает карточки за 7 дней и предварительный просмотр дайджеста за сутки |
| `/opportunities ID STATE` | Меняет состояние карточки на `new`, `seen`, `interesting`, `rejected` или `in_progress` |

Для аргумента `CHAT_ID` можно указать числовой ID Telegram с его знаком,
публичный `@username` или ссылку вида `https://t.me/username`. Например,
`/allow https://t.me/username draft_only` и `/external @username on`.
Это работает с `/allow`, `/deny`, `/external`, `/forget` и `/limits chat`.
Для группы без публичного имени используйте ID. Разрешение по ссылке
сохраняется по ID, который вернул Telegram. Личный аккаунт должен уже
состоять в группе, чтобы получать оттуда события. Разрешения действуют
без перезапуска.
Если в журнале появится `control_bot_stopped code=409`, для этого токена уже
работает другой poller или настроен webhook. Для управления используйте
отдельного бота с собственным токеном.

### Настройки отправки

Глобальные `global_daily` и `global_rolling` изначально равны нулю.
Для будущих инициатив включите флаг отдельно через
`/allow CHAT_ID auto_reply proactive` и задайте оба бюджета `proactive_daily`.
Кандидаты появляются из свежих событий разрешённых чатов. Сами команды
управления сообщений в очередь личного аккаунта не добавляют.

```text
/limits global_daily 10
/limits global_rolling 10
/limits chat -1001234567890 daily 3
/limits chat -1001234567890 rolling 3
/limits quiet_start 23:00
/limits quiet_end 07:00
```

Это примеры настройки приложения. Календарный бюджет и часы тишины используют
`TIMEZONE`. Скользящий бюджет охватывает последние 24 часа. Равные границы
отключают окно тишины. Временные интервалы и TTL указываются в секундах.
Ссылки по умолчанию закрыты и разрешаются через `allow_links 1` для чата.

## Конфигурация

Окружение процесса имеет приоритет над `.env`, затем используются значения
по умолчанию. Относительные пути отсчитываются от рабочего каталога.

- `MODE` принимает `OBSERVE`, `DRAFT` или `AUTO`. Значение используется
  для новой БД, по умолчанию `OBSERVE`. Дальше рабочий режим и пауза читаются
  из SQLite. Пауза хранится отдельным флагом и сохраняет выбранный режим.
- `DRY_RUN` по умолчанию равен `true` и читается при каждом старте.
  Используйте `true` или `false`. При `true` шлюз отклоняет кандидатов и
  воркер не запускает цикл исходящей отправки.
- `TIMEZONE` принимает имя из базы IANA. По умолчанию `Europe/Kyiv`.
  Время в SQLite хранится в UTC как Unix timestamp.
- `DATA_DIR` по умолчанию равен `data`. Имя БД — `companion.sqlite3`.
  Сессия по умолчанию лежит там же в `telegram.session`. Путь можно переопределить
  через `TELEGRAM_SESSION_PATH` при локальном запуске. Compose фиксирует
  оба пути внутри постоянного тома.
- `API_ID`, `EXPECTED_ACCOUNT_ID` и `OWNER_TELEGRAM_ID` — положительные
  целые числа. `ADMIN_IDS` — JSON-массив чисел, например `[123456789]`.
  `API_HASH`, `CONTROL_BOT_TOKEN` и `OPENROUTER_API_KEY` — секреты.
  Для запуска без Telegram оставьте `API_ID`, `API_HASH` и
  `EXPECTED_ACCOUNT_ID` незаданными. Частичная настройка этих трёх полей
  вызывает ошибку при запуске воркера.

## Стиль и OpenRouter

### Примеры датасета

В каталоге [examples](examples/) лежат два независимых примера с вымышленными сообщениями.

- [result.example.json](examples/result.example.json) — JSON-экспорт одного чата Telegram Desktop. Для владельца с ID `42` импортёр выберет две реплики с `from_id: "user42"` и пропустит реплику собеседника. Поле `text` может быть строкой или массивом фрагментов с форматированием.
- [owner-messages.example.jsonl](examples/owner-messages.example.jsonl) — готовый корпус реплик владельца. Каждая строка содержит один объект с полем `text`. Автор в этом формате общий для всего файла, поэтому включайте в свой корпус только собственные сообщения. [Пример persona.yaml](examples/prompts/persona.yaml) связывает файл с владельцем через `style_corpus.owner_id`.

Для проверки из корня проекта откройте отдельное окно PowerShell после установки зависимостей. Команды создадут демонстрационную базу в `data/style-demo/`. Подключение к Telegram и ключ модели для импорта не требуются.

```powershell
$env:OWNER_TELEGRAM_ID = "42"
$env:DATA_DIR = "data/style-demo"
.\.venv\Scripts\python.exe -m aibottelegram style-import examples/result.example.json
$env:PERSONA_PATH = "examples/prompts/persona.yaml"
.\.venv\Scripts\python.exe -m aibottelegram style-import
```

Каждый импорт покажет в журнале `messages=2`. Для собственного экспорта укажите свой числовой `OWNER_TELEGRAM_ID` в `.env` и положите экспорт в `dataSet/result.json`. Для готового JSONL сохраните реплики в `data/persona/owner-messages.jsonl`, перенесите блок `style_corpus` в локальный `prompts/persona.yaml` и замените `owner_id` и `path`. Путь в этом блоке считается от родительского каталога папки `prompts`.

### Импорт собственного экспорта

При запуске приложение индексирует локальный корпус, указанный в
`prompts/persona.yaml`. Чтобы использовать оригинальный экспорт Telegram
Desktop, запустите локальный импорт.

```powershell
.\.venv\Scripts\python.exe -m aibottelegram style-import .\dataSet\result.json
.\.venv\Scripts\python.exe -m aibottelegram models-check
```

Импорт понимает полный экспорт и JSON отдельного чата до 2 ГиБ. Он
проверяет `from_id` по ID владельца, пропускает пересылки и сообщения через
ботов, отбрасывает повторные записи одного сообщения и пропускает повторный
импорт файла с тем же SHA-256. SQLite хранит статистику и отобранные
короткие примеры. Для запроса выбирается до пяти примеров по языку,
ситуации и длине. В отбор попадает только ограниченная разговорная
лексика. Это позволяет исключить личные истории, ссылки и контакты из
стилевых примеров. Грубые оценки языка и тона видны в локальном профиле.

Модели настраиваются в `models.yaml`. Бесплатные маршруты имеют суффикс
`:free` и нулевой потолок цены. Каждый платный маршрут явно перечислен
в `paid_models` с провайдером и потолком цены за миллион токенов.
Приложение сверяет маршрут со свежим каталогом OpenRouter и передаёт
потолок цены в каждом запросе. В опубликованном шаблоне роли имеют
`primary: null`. Для генерации укажите доступную модель в роли
`conversation`. Остальные роли и резервные модели настраиваются отдельно.
Тире в обычном
тексте нормализуются локально перед проверкой.

`OPENROUTER_API_KEY` задаётся локально. `models-check` запрашивает публичные
метаданные и не вызывает генерацию. Локальные счётчики включают все попытки,
в том числе ошибки. Общая квота провайдера может отличаться от локального
бюджета. Подтверждённая квота бесплатного тарифа ставит на паузу бесплатные
маршруты. При неоднозначном 429 приложение временно блокирует весь маршрут
аккаунта. Проверить расход можно через `/providers`. Команда
`/reset_quota` сбрасывает локальные бесплатные счётчики. Ограничения
платных запросов и квоты самого OpenRouter действуют отдельно.

Для замены ключа без перезапуска задайте `OPENROUTER_API_KEY_FILE` в
`.env`. В Docker используйте `/app/data/openrouter-key.json`. Пока
текущий ключ ещё действителен, выполните однократный импорт из
`OPENROUTER_API_KEY` и перезапустите приложение для загрузки настройки.

```sh
docker compose exec companion python -m aibottelegram openrouter-key --from-env
docker compose up -d companion
```

Для дальнейшей замены создайте новый обычный API-ключ OpenRouter.
В личном чате с управляющим ботом отправьте
`/openrouter_key` и в течение трёх минут ответьте на запрос бота одним
ключом. Бот удаляет сообщение перед проверкой и исключает обнаруженные
ключи из памяти. Само сообщение проходит через Telegram.

Для скрытого ввода через SSH выполните команду ниже в интерактивном терминале. Новый
ключ вводится скрыто. Команда проверяет ключ через API и атомарно
обновляет файл в постоянном томе. Следующий запрос возьмёт ключ из файла.
Счётчики и ожидание после `429` продолжают действовать.

```sh
docker compose exec companion python -m aibottelegram openrouter-key
```

Если нужно остановить работу до сброса квоты, отправьте `/stop`
управляющему боту. Он приостановит генерацию, анализ, сводки, дайджест
и отправку. Входящие события будут сохраняться локально. Запрос,
который уже ушёл провайдеру, может быть учтён в квоте. Для продолжения
отправьте `/resume`.

Для подготовки ответов OpenRouter получает короткие отфильтрованные фрагменты из
групп, для которых владелец выполнил `/external CHAT_ID on`. Команда
поддерживает группы без публичного `@username`. Если ранее разрешённая
публичная группа потеряла username, выполните команду заново для разрешения
генерации в закрытой группе. Разговорный фильтр пропускает обычную лексику
любой тематики, маскирует распознанные ссылки, контакты, числа и имена
и исключает сообщения с некоторыми чувствительными формулировками.
В черновиках замены видны модели как метки на месте исходных фрагментов.
Например, `[видео youtube]`, `[внешняя ссылка]` или `[почта скрыта]`.
Для ссылки на коллекционный подарок Telegram из адреса извлекаются
название коллекции и номер. Сам адрес остаётся скрыт, страница не открывается.
Эти эвристики не гарантируют полной анонимности.
Личные диалоги и исходный экспорт остаются на компьютере.
Провайдеры бесплатных маршрутов могут хранить содержимое запросов.

## Память и автономное общение

После `/allow CHAT_ID` бот сохраняет новые сообщения, ответы и правки
локально. Память разделена по аккаунту, чату и теме. Поиск по FTS5,
цепочка ответов и выборка свежих реплик дают контекст для планировщика.
Сводка хранит ID опорных сообщений. Удаления обрабатываются по событиям
Telegram, которые могут поступать неполностью. `/forget` очищает историю
этого чата сразу. Новые события снова будут сохраняться при действующем
`/allow`. Срок хранения настраивается через `MEMORY_RETENTION_DAYS` и
по умолчанию составляет 30 дней.

```text
Событие Telegram → проверка прав → локальный фильтр и очередь
  → контекст темы → решение об участии → текст → проверка текста
  → DRAFT → /drafts → /approve ID → OutboundGateway → Telegram
  → AUTO → OutboundGateway → Telegram
```

Чтобы посмотреть черновики, задайте `/allow CHAT_ID draft_only`, затем
выполните `/external CHAT_ID on` и `/mode draft`. При настроенном OpenRouter бот
оценивает новые сообщения и сохраняет подходящие ответы. `/drafts`
показывает их даже с `DRY_RUN=true` и нулевыми лимитами отправки.
Черновик доступен для одобрения до 10 минут, пока его контекст актуален.
Отправка по `/approve ID` требует `DRY_RUN=false` и проходит через
тот же шлюз, включая проверку паузы, прав чата и лимитов.

Для автономного общения выберите группу и выполните следующие команды с её ID.

```text
/allow CHAT_ID auto_reply
/external CHAT_ID on
/limits global_daily 10
/limits global_rolling 10
/mode auto
```

Включите отправку через `DRY_RUN=false` в `.env` и перезапустите приложение.
Если включена пауза, снимите её через `/resume`. Без любого из этих условий
пользовательский аккаунт не отправит реплику. В режиме `AUTO` модель может
предложить ответ или вопрос без упоминания аккаунта. Планировщик оценивает
вопросы, обращения и приглашения к разговору. Реплику без обращения он
может оценить по свежим сообщениям других участников, даже если она короткая.
Такая фоновая проверка выполняется не чаще раза в 15 минут на группу.
Короткая реакция, шутка или встречный вопрос подходят для продолжения
разговора. Минимальная оценка модели требуется для инициативной темы.
Инициативная тема
требует отдельного разрешения и свежего содержательного повода. Повтор
инициативы блокируется, пока предыдущая отправка остаётся без ответа.
Шлюз повторно проверяет разрешения, ревизию памяти, лимиты и адресата.

## Возможности и дайджест

Локальный фильтр ищет сигналы спроса в разрешённых чатах. Карточка
разделяет заявленный бюджет и сроки от предварительной оценки, хранит
источник и группирует повторные публикации. Вес критериев можно задать
в `OPPORTUNITY_WEIGHTS` как JSON-массив из пяти чисел с суммой 100.
Порядок весов соответствует навыкам, спросу, актуальности, реалистичности
и затратам на старт. Модель дополнительно оценивает часть сигналов из
публичных чатов с разрешённой внешней обработкой.

При наличии находок управляющий бот отправляет дайджест один раз за
календарную дату. По умолчанию время `DIGEST_TIME=19:00` в `TIMEZONE`
(`Europe/Kyiv`). `DIGEST_ENABLED=false` отключает расписание.
При неопределённом результате доставки дайджест за ту же дату
автоматически не повторяется. Источники на этом этапе берутся из Telegram.

| Данные | Где хранятся |
| --- | --- |
| Миграции, выбранный режим и пауза | `schema_migrations` и `runtime_state` уже созданы |
| Разрешение чата | `chats` уже создана. Ключ — аккаунт и чат. Без записи применяется запрет |
| Сообщения, темы и сводки | `messages`, `topics`, `topic_messages`, `chat_summaries` и FTS5 с фильтром по чату и треду |
| Возможности и дайджест | `opportunities`, `opportunity_sources` и `digest_runs` |
| Лимиты и отправки | `send_limits`, `outbound_state`, `chat_send_state`, `outbound_context` и `outbox`. Резерв в очереди учитывается в бюджете транзакционно |

В очереди помещается до 64 ожидающих кандидатов. После смены контекста или
сброса соединения кандидат отменяется. Замеченная ручная реплика отменяет
очередь для своего чата и запускает паузу по `manual_cooldown`. Приложение
видит ручные сообщения в пределах полученных Telegram-событий.

Если попытка прервалась или подтверждение доставки потерялось, результат
сохраняется в `unknown`, расход удерживается, управляющий бот сообщает о
событии. Такую отправку приложение автоматически не повторяет.

Оригинальный экспорт остаётся в `dataSet/`. Он исключён из Git и Docker
контекста. Локальный профиль можно заново построить из экспорта или корпуса,
указанного в персоне.

## Журнал решений

Сопоставляйте записи по `chat_id` и `message_id`. `telegram_message_observed`
означает получение события. Планировщик объединяет близкие сообщения
одной темы и отсеивает неподходящие реплики. `participation_decision`
показывает действие модели и оценку. `generation_started` означает попытку
сгенерировать текст. `participation_result` показывает итог или причину
остановки. При `outcome=draft_saved` текст доступен через `/drafts`.
`ambient_no_recent_exchange` означает, что бот не нашёл свежей реплики
другого участника для фоновой проверки. `ambient_cooldown` означает,
что такая проверка уже была в этой группе за последние 15 минут.
`outcome=queued` означает постановку в очередь. Статус отправки смотрите
через `/status`. Текст сообщений и запросов в этих записях отсутствует.

## Резервное копирование и восстановление

Запустите `backup` из другого терминала. Он копирует SQLite через Backup API,
проверяет целостность снимка и хранит последние семь копий в `data/backups`.
Можно указать другой каталог и число снимков через `--keep`.

```powershell
.\.venv\Scripts\python.exe -m aibottelegram backup
```

```sh
docker compose exec -T companion python -m aibottelegram backup
```

Для проверки восстановления укажите новый каталог `DATA_DIR` и путь
к снимку. Команда откажется перезаписывать существующую базу. Для
восстановления рабочего экземпляра сначала остановите приложение,
сохраните прежнюю БД вместе с её служебными файлами, затем восстановите
копию в пустой каталог. После запуска проверьте режим и права чатов.

```powershell
$env:DATA_DIR = '.\data\restore-check'
.\.venv\Scripts\python.exe -m aibottelegram restore '.\data\backups\ИМЯ_СНИМКА.sqlite3'
Remove-Item Env:DATA_DIR
```

```sh
docker compose exec -T -e DATA_DIR=/app/data/restore-check companion \
  python -m aibottelegram restore /app/data/backups/ИМЯ_СНИМКА.sqlite3
```

Для защиты от потери диска храните копию вне сервера с ограниченным
доступом. SQLite содержит историю и настройки. Telegram-сессия и
`.env` хранятся отдельно. Сессию копируйте только после остановки клиента,
по защищённому каналу, с доступом только владельцу. При утрате сессии
выполните `login` заново. Запускайте одну копию клиента на сессию.

## Офлайн-прогон и замеры

`replay` принимает обезличенный JSONL. В каждой строке укажите `t`
(секунды от начала), синтетические `chat` (отрицательный ID), `message`
и `sender` и обезличенный `text`. Отсортируйте строки по `t`. Дополнительно
можно задать `thread`, `reply_to`, `outgoing`, `bot` и `addressed`.
Сырые экспорты Telegram Desktop предварительно преобразуйте.

```json
{"t":0,"chat":-42,"message":1,"sender":2,"text":"Подскажите, как запустить Docker?"}
```

```powershell
.\.venv\Scripts\python.exe -m aibottelegram replay .\data\replay.jsonl --mode auto
```

Отчёт в JSONL содержит решение для каждой реплики, отфильтрованный
контекст при обращении к имитации модели и итоговые счётчики со временем
прогона. Используются временная база, виртуальное время, имитация модели
и Telegram. Группы из файла разрешены только внутри симуляции. Лимиты
симуляции составляют 10 сообщений по аккаунту и 3 по группе. Этот прогон
проверяет логику приложения. Качество реальных моделей проверяется отдельно.

На хосте с Docker и Compose выполните `python scripts/docker_smoke.py`.
Скрипт поднимает изолированный сервис и временный том, проверяет healthcheck,
создаёт и восстанавливает снимок, выводит CPU и память через `docker stats`.
Для проверки используется пустая конфигурация, сеть сервиса отключена.
